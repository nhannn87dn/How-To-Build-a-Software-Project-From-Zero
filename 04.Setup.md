# Giai đoạn 4: Setup (khởi tạo dự án)

Giai đoạn này biến thiết kế thành một **bộ khung chạy được xuyên mọi tầng** (React → NestJS → SQL Server) trước khi viết tính năng nào. Nó chưa làm story nào; việc của nó là đảm bảo mọi story sau đó chỉ tốn công vào nghiệp vụ, không vướng môi trường.

**Đầu vào:** `docs/03-design/` (kiến trúc, ERD, quy ước API, ADR-001 đến 006).
**Đầu ra:** repo chạy được bằng vài lệnh, có CI xanh, có tài liệu hướng dẫn chạy.
**Quỹ giờ:** khoảng 22 giờ (PRD mục 5.3), tức đợt 1.

## Quy trình 9 bước

### Bước 1: Chuẩn bị môi trường máy
| Công cụ | Ghi chú |
|---|---|
| Node.js bản LTS hiện hành + npm | Ghim phiên bản bằng file `.nvmrc` để máy và CI dùng giống nhau |
| Git | Cấu hình tên/email; nên bật ký commit nếu bạn quen |
| Docker | Chạy SQL Server cho dev; nếu máy dùng chip ARM, kiểm tra trước khả năng chạy image SQL Server |
| VS Code + extension | ESLint, Prettier, EditorConfig |
| Công cụ xem database | Azure Data Studio (đa nền tảng) hoặc SSMS (Windows) |

### Bước 2: Repo và quy trình Git
- **Một repo (monorepo)** gồm `backend/`, `frontend/`, `docs/`, `docker-compose.yml`, `README.md`. Lý do: một người làm, một lịch sử commit, tài liệu nằm cùng code nên dễ giữ đồng bộ; chưa cần công cụ monorepo riêng.
- Chép các tài liệu đã soạn vào `docs/` (`01-prd.md`, `02-user-stories.md`, `03-design/`, tài liệu auth).
- Nhánh: `main` (ổn định), `develop` (tích hợp), `feature/*`, `fix/*`. Bảo vệ `main`: chỉ nhận merge qua CI xanh.
- `.gitignore` (node_modules, `.env`, build, dữ liệu DB cục bộ), `.editorconfig`, `.nvmrc`.

### Bước 3: Database dev bằng Docker
```yaml
# docker-compose.yml
services:
  db:
    image: mcr.microsoft.com/mssql/server:2022-latest
    environment:
      ACCEPT_EULA: "Y"
      MSSQL_SA_PASSWORD: ${DB_SA_PASSWORD}   # lấy từ .env, không hard-code
    ports: ["1433:1433"]
    volumes: [mssql_data:/var/opt/mssql]
volumes:
  mssql_data:
```
- Mật khẩu SA phải đủ phức tạp (SQL Server từ chối mật khẩu yếu).
- Hai database riêng: `lms_dev` (phát triển) và `lms_test` (e2e), tạo bằng một script khởi tạo.
- **Không dùng tài khoản SA trong ứng dụng**: tạo login/user riêng có quyền trên đúng database đó (nguyên tắc quyền tối thiểu, thói quen tốt từ đầu).

### Bước 4: Khung backend (NestJS)
Theo `architecture.md` mục 5, 6, 10; làm theo thứ tự này để mỗi lớp kiểm tra được ngay:

1. `nest new` rồi dọn code mẫu; bật `strict` trong `tsconfig`.
2. **`config/`**: đọc biến môi trường và kiểm tra bằng Zod khi khởi động (thiếu biến thì không chạy); tạo `backend/.env.example`.
3. **`database/`**: data source TypeORM (ADR-004), script `migration:generate`, `migration:run`, `migration:revert`; **không bật `synchronize`**. Tạo một migration rỗng/đầu tiên để chứng minh quy trình chạy.
4. **`common/`**: `ValidationPipe` (whitelist, forbidNonWhitelisted, transform), exception filter trả `{ success:false, message, code }`, response interceptor bọc `{ success, data, message }`, middleware `X-Request-Id`.
5. Prefix `/api/v1`, `helmet`, `cookie-parser`, `@nestjs/throttler` (chuẩn bị cho ADR-006 và rate limit), CORS chỉ cho domain frontend và bật credentials.
6. **`health/`**: `GET /api/v1/health` kiểm tra kết nối database.
7. Logger có cấu trúc (JSON), không ghi dữ liệu nhạy cảm.

### Bước 5: Khung frontend (React)
1. Vite + React + TypeScript (strict).
2. `app/` (router, providers: `QueryClientProvider` theo ADR-005), `features/`, `shared/` đúng cấu trúc ở `architecture.md`.
3. **Proxy của dev server** chuyển `/api` sang backend, để trình duyệt thấy cùng một origin: đây là điều kiện để cookie refresh token của ADR-006 chạy được khi phát triển.
4. `shared/lib/http.ts` (lớp HTTP duy nhất): gắn access token, xử lý 401 một lần refresh; `errorMessages.ts`; `formatDateTime()` cho GMT+7 `dd/mm/yyyy HH:mm`.
5. Thành phần dùng chung tối thiểu: `LoadingState`, `ErrorState`, `EmptyState`, `AppShell` rỗng.

### Bước 6: Công cụ chất lượng
- ESLint + Prettier dùng chung cấu hình cho cả hai phía; script `lint`, `typecheck`, `test`, `build`.
- Jest cho backend (unit trong thư mục module, e2e trong `test/`).
- Tuỳ chọn: Husky + lint-staged để lint trước khi commit. Đây là thư viện ngoài, lợi ích là chặn code lỗi sớm; nếu muốn tối giản, để CI làm việc này là đủ.

### Bước 7: CI cơ bản
Giả định Git host là GitHub (nếu khác, cấu trúc tương tự). Mỗi lần push/PR:
1. Cài đặt (có cache), `lint`, `typecheck`
2. Unit test
3. E2E với **SQL Server chạy dạng service container**, chạy migration rồi mới test
4. `build` cả hai phía

Mục tiêu giai đoạn này: pipeline **xanh** với chỉ một vài test mẫu (ví dụ test `/health`).

### Bước 8: Spike rủi ro (mỗi cái 2-3 giờ, có giới hạn thời gian)
Chạy thử những thứ dễ làm hỏng kế hoạch nếu để muộn:

| Spike | Câu hỏi cần trả lời | Liên quan |
|---|---|---|
| Migration trên SQL Server | Sinh và chạy migration, rồi revert được không? | ADR-004 |
| Khoá bi quan | Transaction + khoá hàng khoá học trên SQL Server hoạt động đúng khi hai request đồng thời? | `architecture.md` mục 8 (duyệt vào lớp đủ chỗ) |
| Cookie refresh qua proxy | Cookie `HttpOnly; SameSite=Strict` gắn được và gửi lại qua proxy dev? | ADR-006 |

Kết quả ghi lại ở `docs/03-design/` (ví dụ `spikes.md`); spike nào thất bại thì **cập nhật ADR hoặc thiết kế trước khi vào đợt 2**, không phải sau.

### Bước 9: Nghiệm thu bằng walking skeleton mỏng + tài liệu chạy
**Walking skeleton của giai đoạn 4:** từ máy sạch, theo `README.md` chạy được:

```
docker compose up -d      →  SQL Server lên
backend: npm run migration:run  →  database có migration đầu tiên
backend: npm run start:dev      →  GET /api/v1/health trả { success: true, data: { database: "up" } }
frontend: npm run dev           →  trang chủ gọi /health qua proxy và hiện "Hệ thống hoạt động"
CI                              →  xanh
```
Đây **chưa phải** walking skeleton của đợt 2 (đăng nhập, tạo khoá, thấy khoá trên giao diện); đó là việc đầu tiên của giai đoạn 5.

## etup bước 1: Repo monorepo và SQL Server bằng Docker

```yaml
# docker-compose.yml
services:
  db:
    image: mcr.microsoft.com/mssql/server:2022-latest
    platform: linux/amd64
    environment:
      ACCEPT_EULA: "Y"
      MSSQL_SA_PASSWORD: ${MSSQL_SA_PASSWORD:?Hãy đặt MSSQL_SA_PASSWORD trong file .env}
    ports:
      - "${DB_PORT:-1433}:1433"
    volumes:
      - mssql_data:/var/opt/mssql
    healthcheck:
      test: ["CMD-SHELL", "/opt/mssql-tools18/bin/sqlcmd -C -S localhost -U sa -P \"$$MSSQL_SA_PASSWORD\" -Q \"SELECT 1\" -b"]
      interval: 10s
      timeout: 5s
      retries: 10
      start_period: 20s
    restart: unless-stopped

  # Chạy một lần sau khi db sẵn sàng: tạo database, login và user cho ứng dụng
  db-init:
    image: mcr.microsoft.com/mssql/server:2022-latest
    platform: linux/amd64
    depends_on:
      db:
        condition: service_healthy
    environment:
      MSSQL_SA_PASSWORD: ${MSSQL_SA_PASSWORD:?Hãy đặt MSSQL_SA_PASSWORD trong file .env}
      DB_APP_PASSWORD: ${DB_APP_PASSWORD:?Hãy đặt DB_APP_PASSWORD trong file .env}
    volumes:
      - ./docker/db/init.sql:/init/init.sql:ro
    entrypoint: ["/bin/bash", "-c"]
    command:
      - >
        /opt/mssql-tools18/bin/sqlcmd -C -S db -U sa -P "$$MSSQL_SA_PASSWORD" -b
        -i /init/init.sql -v APP_PASSWORD="$$DB_APP_PASSWORD"
    restart: "no"

volumes:
  mssql_data:
```

```sql
-- docker/db/init.sql
-- Chạy bằng sqlcmd. Idempotent: chạy lại nhiều lần vẫn an toàn.
SET NOCOUNT ON;

-- Collation không phân biệt hoa/thường và dấu: tìm "nguyen" ra "Nguyễn" (xem erd.md)
IF DB_ID(N'lms_dev') IS NULL CREATE DATABASE lms_dev COLLATE Vietnamese_100_CI_AI;
IF DB_ID(N'lms_test') IS NULL CREATE DATABASE lms_test COLLATE Vietnamese_100_CI_AI;
GO

-- Tài khoản ứng dụng: không dùng sa. Đổi mật khẩu trong .env rồi chạy lại là cập nhật theo.
IF NOT EXISTS (SELECT 1 FROM sys.server_principals WHERE name = N'lms_app')
    CREATE LOGIN lms_app WITH PASSWORD = N'$(APP_PASSWORD)';
ELSE
    ALTER LOGIN lms_app WITH PASSWORD = N'$(APP_PASSWORD)';
GO

-- Dev/test: lms_app là db_owner của đúng 2 database này (cần để chạy migration).
-- Production sẽ tách tài khoản chạy migration và tài khoản chạy ứng dụng (làm ở giai đoạn triển khai).
USE lms_dev;
IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = N'lms_app')
    CREATE USER lms_app FOR LOGIN lms_app;
IF IS_ROLEMEMBER(N'db_owner', N'lms_app') = 0
    ALTER ROLE db_owner ADD MEMBER lms_app;
GO

USE lms_test;
IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = N'lms_app')
    CREATE USER lms_app FOR LOGIN lms_app;
IF IS_ROLEMEMBER(N'db_owner', N'lms_app') = 0
    ALTER ROLE db_owner ADD MEMBER lms_app;
GO

PRINT N'Khoi tao xong: lms_dev, lms_test, login lms_app';
GO
```

## Cách chạy và kiểm tra

```bash
# 1. Tạo .env
cp .env.example .env              # bash / macOS / Linux
# Copy-Item .env.example .env     # PowerShell
# Mở .env, điền MSSQL_SA_PASSWORD và DB_APP_PASSWORD

# 2. Khởi động
docker compose up -d
docker compose ps
docker compose logs db-init

# 3. Đăng nhập thử bằng tài khoản ứng dụng (nhập mật khẩu DB_APP_PASSWORD của bạn)
docker compose exec db /opt/mssql-tools18/bin/sqlcmd -C -S localhost -U lms_app -P "<DB_APP_PASSWORD>" -d lms_dev -Q "SELECT DB_NAME() AS db, SUSER_NAME() AS login_name, DATABASEPROPERTYEX('lms_dev','Collation') AS collation"
```

**Kết quả mong đợi:**
- `docker compose ps`: `db` ở trạng thái `healthy`; `db-init` đã thoát (`Exited (0)`).
- `db-init` log có dòng `Khoi tao xong: lms_dev, lms_test, login lms_app`.
- Lệnh `sqlcmd` trả `lms_dev | lms_app | Vietnamese_100_CI_AI`.
- Chạy lại `docker compose up db-init` (hoặc `docker compose run --rm db-init`): vẫn thành công, không báo lỗi trùng.
- `git status` **không** liệt kê file `.env`.

**Gỡ lỗi thường gặp:**
- *`sqlcmd: not found`:* đường dẫn công cụ khác theo phiên bản image; tìm bằng `docker compose exec db find /opt -name sqlcmd` rồi sửa đường dẫn trong `docker-compose.yml`.
- *`Invalid collation`:* đổi `Vietnamese_100_CI_AI` thành `Vietnamese_CI_AI` trong `init.sql`, rồi `docker compose down -v` và chạy lại.
- *Mật khẩu bị từ chối:* chưa đủ độ phức tạp hoặc có ký tự `'` hoặc `$`; sửa trong `.env` (đổi `DB_APP_PASSWORD` thì chạy lại `db-init` là cập nhật theo; đổi `MSSQL_SA_PASSWORD` sau lần chạy đầu cần `down -v`).
- *Cổng 1433 bị chiếm* (máy đã cài SQL Server): đặt `DB_PORT=14330` trong `.env`.
- *Container `db` thoát ngay:* thường do thiếu RAM; tăng bộ nhớ cho Docker Desktop lên ít nhất 2 GB.
